Node.js = Runtime Environment (코드를 직접 실행해주는 환경) = V8을 품은 거대한 C++ 프로그램

- 프로그래밍 언어 자체는 단순히 텍스트에 불과. 이 텍스트를 읽고 컴퓨터가 알아듣게 번역해서 실행해 주는 토대가 런타임

JS Code -> JS Engine(SpiderMonkey, V8 ...) -> CPU가 이해하는 기계어

#### 자바스크립트 변천사

JS -> ByteCode -> VM -> 기계어

- 통역 시간이 병목이 되어 실행 속도가 느렸었음

V8은 중간 단계를 없애고 기계어로 직행하는 '직접 컴파일'을 도입
JS -> 기계어

#### Node.js 설치의 진짜 의미

단일 C++ 실행파일을 추가하는 과정이며, 설치된 파일은 운영체제의 환경변수(PATH)에 등록되어 위치를 각인하는 것.

[node.exe]를 환경변수(PATH)에 위치 등록

- 환경변수: 실행파일을 찾는 길잡이
- PATH가 없다면 파일을 실행할 때마다 길고 복잡한 절대경로를 입력해야 함
- PATH 등록 시 짧은 명령어만으로도 운영체제가 숨겨진 실행파일을 찾아냄.

```
// PATH 등록 전
> C:\Program Files\nodejs\node.exe index.js

// PATH 등록 후
> node index.js
```

#### 3단계 아키텍처

JS(지시) -> V8(통역) -> C++ Bindings(소통 및 실행) -> OS

1. 작업 지시서 작성 (JS 프로그래밍 진행)
2. V8 엔진의 통역 (JS로 작성된 지시서를 수신하여 의도를 해석하는 통역사)
3. C++ Binding (번역된 지시를 바탕으로 운영체제에 파일이나 네트워크 작업을 직접 지시함)

#### C++ 코어를 돕는 다양한 조력자들

- OpenSSL (암호화)
- zlib (압축)
- npm (패키지 관리)
- GYP (C++ 빌드)
- libuv (C Library - 파일 시스템 & 비동기 작업)

터미널에서 node 실행 시 운영체제에 단일 프로세스(Process) 활성화 -> 운영체제 작업 관리자에 고유한 PID와 메모리 할당량을 가진 하나의 프로세스가 켜짐

- PID는 OS가 시스템 자원과 메모리를 정확히 통제하기 위한 식별 기준임

```
node app.js // 1개의 프로세스 켜짐 (Process {PID: 10452, Memory: 45MB})
```

libuv는 프로세스 내부에서 실질적인 작업을 수행

- libuv는 4명의 일꾼(스레드 풀)을 가짐
- libuv 내부의 스레드풀(일꾼 대기실)은 무거운 작업을 대기
- 무거운 파일 시스템(fs) 작업은 스레드 풀의 4명 일꾼이 전담
  ```
  무거운 파일 시스템 작업(fs.readFile()) -> [Thread Pool(4)]
  ```
- 네트워크 통신 시 libuv는 스레드 풀을 전혀 사용하지 않고, 운영체제의 비동기 네트워크 기능에 직접 위임
  ```
  HTTP Requests -> [OS Kernel]
  ```
  이 효율성으로 인해 스레드 소모 없이 많은 트래픽을 효율적으로 처리할 수 있게 됨
