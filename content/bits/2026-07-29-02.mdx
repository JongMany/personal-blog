#### 동기식 블로킹 (Synchronous Blocking, 전통적 서버의 핵심 아키텍처)

- 동기: 앞선 작업이 끝나야 다음 작업을 시작하도록 시간과 순서를 엄격하게 맞춘다는 뜻
- 블로킹: 길을 막고 서서 다음 작업으로 넘어가지 못하게 전체 흐름을 멈춰 세운다.

식당 비유

- 식당의 웨이터가 손님의 주문을 받고 난 뒤 요리가 끝나기 전까지 주방 앞에 가만히 서서 기다리는 경우
  - 웨이터: 일을 처리하는 스레드
  - 주방: 데이터 저장소 (DB / File System)
  - 손님: Client Request
- 손님이 100명으로 늘어나면 웨이터도 100명을 고용해야 하는 구조
  - 요청마다 새 일꾼(스레드) 강제 생성
- 동시 접속 폭주 → 자원 순식 간에 고갈 (Server Down)

```typescript
const data = db.querySync("SELECT * FROM users"); // 주방에 넣은 주문

console.log("데이터 조회가 끝남", data);
```

#### 비동기식 논블로킹

- 비동기: 앞선 작업이 끝날 때까지 멈춰서 기다리지 않는 것
- 논블로킹: 멈춰 서서 길을 막지 않고 다음 일로 넘어가는 것

식당 비유

- 홀을 담당하는 단 한 명의 빠르고 효율적인 웨이터만 존재
  - 싱글 스레드
- 유일한 웨이터는 1번 테이블의 주문을 받아 받은 주문을 바로 주방(OS/Database)에 넘김
  - 무거운 작업은 OS/DB의 몫
- 요리를 기다리지 않고, 즉각 2번 테이블로 이동해 다음 주문을 받음
- 주방은 주문받은 요리를 독립적으로 완성하고, 완성된 요리는 순서대로 대기열에 오름
  - 대기열 = Event Queue
- 웨이터는 홀을 도는 틈틈이 이 대기열을 확인(Event Loop)하고 완성된 요리를 손님에게 서빙(Callback/Response)

```typescript
const data = db.query("SELECT * FROM users", (error, data) => {
  console.log("요청이 완료되고 나서 실행됨.", data);
});

console.log("요청을 OS에 넘기고, 다음 동작을 실행");
```

#### Node.js의 강점과 약점

강점: I/O 작업이 많은 경우

- 데이터 입출력 작업의 경우, 스레드를 멈추지 않을 수 있기 때문에 I/O 작업이 많은 케이스에서 유리함

약점: CPU 집약적인 작업이 많은 경우

- CPU 집약적인 작업은 주방에게 맡길 수 없고 웨이터가 직접 처리해야 하기 때문임.
  - 작업을 하느라 이벤트 루프가 막혀서 블로킹 현상이 발생함

CPU 집약적인 작업

- 암호화 및 해싱: 비밀번호를 bcrypt로 암호화하거나, 대용량 데이터를 복호화하는 과정.
- 이미지 및 동영상 처리: 사진 크기를 조절(Resizing)하거나, 동영상 코덱을 변환(Transcoding)하는 연산.
- 대규모 데이터 파싱: 수십만 줄의 JSON 데이터를 객체로 변환하거나(JSON.parse), XML 등을 파싱하는 작업.
- 압축 및 해제: 대용량 파일을 ZIP이나 Gzip으로 압축하는 과정.
- 복잡한 수학적 계산: 인공지능 모델의 추론(Inference), 대규모 배열의 정렬, 복잡한 통계 수치 산출

CPU 집중 작업 격리

1. worker_threads 모듈을 사용해 libuv의 스레드 풀과는 완전히 분리된 별도의 자바스크립트 실행 환경(워커)을 띄우기
2. 메인 Node.js 서버는 API 게이트웨이 역할만 하고 무거운 연산은 AWS SQS 등 메시지 큐를 통해 Python 기반의 독립된 마이크로서비스로 넘겨버리는 아키텍처 설계
